## 1. 서론

### 1.1 목적

본 요구사항 정의서는 NOTEAI 프로젝트의 기능, 성능, 설계, 구현 요구사항을 정의합니다. 개발팀, QA팀, 이해관계자가 프로젝트의 범위와 목표를 명확히 이해하도록 작성되었습니다.

### 1.2 범위

NOTEAI는 연구원과 개발자를 위한 **AI 기반 노트 관리 및 협업 플랫폼**입니다.

**범위 내:**
- 사용자 관리 (회원가입, 로그인, 프로필)
- 노트 관리 (CRUD, 버전 관리)
- AI 기능 (요약, 키워드 추출, 분류)
- 협업 기능 (공유, 댓글, 팀)
- 검색 및 필터링
- 대시보드 및 통계

**범위 밖:**
- 모바일 네이티브 앱 (웹앱만 지원)
- 실시간 협업 편집 (차후 개발)
- AI 모델 자체 개발 (기존 모델 사용)

## 2. 전체 설명

### 2.1 제품 개요

NOTEAI는 다음을 제공합니다:

1. **구조화된 노트 작성**: 마크다운 기반 에디터
2. **AI 기반 처리**: 자동 요약, 키워드 추출, 자동 분류
3. **협업 기능**: 공유, 댓글, 팀 관리
4. **강력한 검색**: 전문 검색 + 시맨틱 검색
5. **인사이트 대시보드**: 통계, 추천, 활동 추적

### 2.2 사용자 특성

| 사용자 유형 | 설명 | 주요 기능 |
|-----------|------|---------|
| **연구원** | 학술 논문, 연구 노트 작성 | 요약, 키워드, 분류, 팀 협업 |
| **개발자** | 기술 문서, 코드 스니펫 작성 | 마크다운, 코드 블록, 공유 |
| **학생** | 강의 노트, 학습 자료 | 카테고리 정리, 검색, 추천 |
| **팀 리더** | 팀 프로젝트 관리 | 팀 관리, 권한 설정, 활동 추적 |

### 2.3 운영 환경

**클라이언트:**
- 웹 브라우저 (Chrome, Firefox, Safari, Edge 최신 버전)
- 데스크톱 OS (Windows, macOS, Linux)
- 태블릿 (iPad 등, 반응형 디자인)

**서버:**
- Python 3.10+
- FastAPI 웹 프레임워크
- SQLite (개발) / PostgreSQL (프로덕션)
- Linux/Windows 호스트

## 3. 기능 요구사항

### 3.1 사용자 관리 (User Management)

#### 3.1.1 회원가입 (Registration)

**식별자**: F001  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
새로운 사용자가 이메일과 비밀번호로 계정을 생성할 수 있습니다.

**입력:**
- 사용자명 (username)
- 이메일 주소
- 비밀번호 (최소 8자, 대문자/소문자/숫자 포함)
- 전체 이름 (선택)

**처리:**
- 중복 사용자명 확인
- 중복 이메일 확인
- 비밀번호 복잡성 검증
- 비밀번호 해싱 (bcrypt)
- 사용자 레코드 생성

**출력:**
- 성공: 계정 생성 완료 메시지, 로그인 페이지로 리다이렉트
- 실패: 오류 메시지

**유효성 검사:**
- 사용자명: 3-50자, 영문+숫자+_만 가능
- 이메일: 유효한 이메일 형식
- 비밀번호: 최소 8자

#### 3.1.2 로그인 (Login)

**식별자**: F002  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
등록된 사용자가 사용자명 또는 이메일과 비밀번호로 로그인합니다.

**입력:**
- 사용자명 또는 이메일
- 비밀번호

**처리:**
- 사용자 찾기
- 비밀번호 확인
- JWT 토큰 생성 (유효기간: 24시간)
- 세션 저장

**출력:**
- 성공: 액세스 토큰, 대시보드로 리다이렉트
- 실패: 오류 메시지 (자격증명 무효)

**보안:**
- 3회 실패 후 계정 잠금 (30분)
- 비밀번호 브루트포스 방지

#### 3.1.3 프로필 관리 (Profile Management)

**식별자**: F003  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
사용자가 프로필 정보를 조회하고 수정합니다.

**입력:**
- 전체 이름
- 소개 (최대 500자)
- 프로필 이미지 (JPG, PNG, 최대 5MB)

**처리:**
- 사용자명 변경 불가 (생성 시에만)
- 이메일 변경 시 인증 필요
- 이미지 업로드 시 타입 검증 및 저장
- 이미지 리사이징 (200x200px)

**출력:**
- 성공: 프로필 업데이트 완료 메시지
- 실패: 오류 메시지

#### 3.1.4 로그아웃 (Logout)

**식별자**: F004  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
사용자가 현재 세션을 종료합니다.

**처리:**
- 토큰 무효화
- 세션 제거
- 쿠키 삭제

**출력:**
- 로그인 페이지로 리다이렉트

### 3.2 노트 관리 (Note Management)

#### 3.2.1 노트 생성 (Create Note)

**식별자**: F010  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
인증된 사용자가 새로운 노트를 생성합니다.

**입력:**
- 제목 (필수, 최대 200자)
- 내용 (마크다운, 필수)
- 카테고리 (선택)
- 태그 (선택, 최대 10개)
- 공개 여부 (기본값: 비공개)

**처리:**
- 입력 유효성 검사
- 노트 레코드 생성
- 생성 시간 기록
- 사용자 ID와 연결

**출력:**
- 생성된 노트 ID
- 노트 조회 페이지로 리다이렉트

#### 3.2.2 노트 조회 (Read Note)

**식별자**: F011  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
사용자가 노트를 조회합니다. 권한에 따라 접근 제어됩니다.

**입력:**
- 노트 ID

**처리:**
- 노트 존재 여부 확인
- 권한 확인 (소유자/공유자/공개 노트)
- 조회수 증가
- 마크다운 렌더링
- 관련 노트 로드

**출력:**
- 노트 정보 (제목, 내용, 작성자, 작성일 등)
- 댓글
- 관련 노트

**권한:**
- 소유자: 항상 접근 가능
- 공유받은 사용자: 권한에 따라
- 공개 노트: 모든 사용자 접근 가능

#### 3.2.3 노트 수정 (Update Note)

**식별자**: F012  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
노트 소유자 또는 편집 권한자가 노트를 수정합니다.

**입력:**
- 제목
- 내용
- 카테고리
- 태그
- 공개 여부

**처리:**
- 권한 확인 (소유자 또는 편집 권한)
- 이전 버전 저장 (버전 관리)
- 노트 업데이트
- 수정 시간 기록
- 변경 내용 저장

**출력:**
- 업데이트 완료 메시지
- 수정된 노트 표시

**제약:**
- 삭제된 노트는 수정 불가
- 권한 없이 수정 시도 시 403 오류

#### 3.2.4 노트 삭제 (Delete Note)

**식별자**: F013  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
노트 소유자가 노트를 삭제합니다 (소프트 삭제).

**입력:**
- 노트 ID
- 확인 (선택)

**처리:**
- 권한 확인 (소유자만)
- deleted_at 타임스탐프 설정 (논리적 삭제)
- 삭제 기록 남기기
- 공유 링크 무효화

**출력:**
- 삭제 완료 메시지
- 노트 목록으로 리다이렉트

**제약:**
- 삭제된 노트는 30일 후 물리적으로 제거
- 삭제 전에 경고 메시지

#### 3.2.5 노트 목록 조회 (List Notes)

**식별자**: F014  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
사용자가 소유하거나 공유받은 노트 목록을 조회합니다.

**입력:**
- 페이지 번호 (기본값: 1)
- 페이지당 아이템 수 (기본값: 10)
- 정렬 기준 (생성일/수정일/제목)
- 정렬 순서 (오름차순/내림차순)

**처리:**
- 권한에 따른 필터링
- 페이지네이션 계산
- 정렬 적용
- 개수 제한 (최대 100개/페이지)

**출력:**
- 노트 리스트 (제목, 미리보기, 작성자, 작성일)
- 전체 개수
- 페이지 정보

### 3.3 노트 조직화 (Note Organization)

#### 3.3.1 카테고리 관리 (Category Management)

**식별자**: F020  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
사용자가 노트를 조직화하기 위해 카테고리를 관리합니다.

**입력:**
- 카테고리 이름 (텍스트)
- 설명 (선택)

**처리:**
- 카테고리 생성/수정/삭제
- 카테고리별 노트 개수 계산
- 사용자별 독립적으로 관리

**출력:**
- 카테고리 목록
- 카테고리별 노트 개수

#### 3.3.2 태그 관리 (Tag Management)

**식별자**: F021  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
사용자가 노트에 태그를 지정하여 조직화합니다.

**기능:**
- 다중 태그 지정 (최대 10개)
- 자동 완성 (기존 태그)
- 태그 검색 및 필터링
- 태그 별 노트 개수 표시

**제약:**
- 태그 최대 길이: 30자
- 특수문자 불허

#### 3.3.3 마크다운 지원 (Markdown Support)

**식별자**: F022  
**우선순위**: CRITICAL  
**상태**: Must-Have

**설명:**
노트 에디터에서 마크다운을 지원합니다.

**지원 문법:**
- 제목 (# ~ ######)
- 굵게, 기울임
- 리스트 (순서, 비순서)
- 링크, 이미지
- 코드 블록 (인라인, 블록)
- 테이블
- 인용구
- 수평선

**처리:**
- 마크다운 유효성 검사
- HTML 렌더링 (XSS 방지)
- 구문 강조 (Syntax Highlighting)
- 미리보기 제공

### 3.4 AI 기능 (AI Features)

#### 3.4.1 자동 요약 (Auto Summarize)

**식별자**: F030  
**우선순위**: HIGH  
**상태**: Nice-to-Have

**설명:**
AI가 노트 내용을 자동으로 요약합니다.

**입력:**
- 요약 길이 선택 (짧음/중간/길음)

**처리:**
- 노트 내용 분석
- 요약 알고리즘 적용 (TextRank 또는 BERT)
- 요약 결과 저장
- 생성 시간 기록

**출력:**
- 요약 텍스트 (50-300자)
- 생성 시간

**제약:**
- 노트 최소 길이: 200자
- 요약 결과 캐싱 (30분)

#### 3.4.2 키워드 추출 (Keyword Extraction)

**식별자**: F031  
**우선순위**: HIGH  
**상태**: Nice-to-Have

**설명:**
AI가 노트에서 중요한 키워드를 추출합니다.

**처리:**
- 텍스트 분석
- 키워드 추출 알고리즘 적용
- 가중치 계산
- 중복 제거
- 태그로 자동 제안

**출력:**
- 키워드 목록 (최대 10개)
- 각 키워드의 가중치 (0-1)

**제약:**
- 노트 최소 길이: 100자
- 추출된 키워드를 태그로 자동 추가 (사용자 승인)

#### 3.4.3 자동 분류 (Auto Classification)

**식별자**: F032  
**우선순위**: MEDIUM  
**상태**: Nice-to-Have

**설명:**
AI가 노트를 자동으로 분류합니다.

**처리:**
- 텍스트 분석
- 분류 모델 적용
- 신뢰도 점수 계산
- 상위 3개 카테고리 제안

**출력:**
- 제안된 카테고리 (최대 3개)
- 각 카테고리의 신뢰도 (%)

**제약:**
- 사용자가 명시적으로 승인 필요
- 사용자 피드백으로 모델 개선

#### 3.4.4 시맨틱 검색 (Semantic Search)

**식별자**: F033  
**우선순위**: MEDIUM  
**상태**: Nice-to-Have

**설명:**
의미 기반 검색으로 관련 노트를 찾습니다.

**입력:**
- 검색어 (자연어)

**처리:**
- 검색어 벡터화
- 노트 내용 벡터화 (임베딩)
- 코사인 유사도 계산
- 유사도 순으로 정렬

**출력:**
- 관련 노트 리스트 (상위 20개)
- 유사도 점수

**제약:**
- 최소 쿼리 길이: 3자
- 계산 시간 제한: 5초

### 3.5 협업 기능 (Collaboration)

#### 3.5.1 노트 공유 (Share Note)

**식별자**: F040  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
노트 소유자가 다른 사용자와 노트를 공유합니다.

**입력:**
- 공유 대상 (사용자 ID 또는 이메일)
- 권한 (read/edit/admin)
- 만료 기한 (선택)

**처리:**
- 권한 검증
- note_collaborators 테이블에 레코드 추가
- 공유 알림 전송
- 만료 시간 설정 (선택)

**출력:**
- 공유 완료 메시지
- 공유 링크 (선택)

**권한 레벨:**
- **read**: 읽기만 가능
- **edit**: 읽기, 편집, 댓글 가능
- **admin**: 읽기, 편집, 댓글, 권한 변경 가능

#### 3.5.2 권한 관리 (Permission Management)

**식별자**: F041  
**우선순위**: HIGH  
**상태**: Must-Have

**설명:**
노트 소유자가 공유 사용자의 권한을 관리합니다.

**입력:**
- 사용자 ID
- 새로운 권한

**처리:**
- 권한 레벨 업데이트
- 권한 변경 알림 전송
- 변경 기록 저장

**출력:**

## 5. 보안 요구사항

### 5.1 인증 & 인가

- **비밀번호**: 최소 8자, 대문자/소문자/숫자 포함
- **비밀번호 해싱**: bcrypt (salt rounds: 12)
- **토큰**: JWT (HS256, 유효기간: 24시간)
- **토큰 갱신**: Refresh Token (7일 유효)
- **세션**: HttpOnly 쿠키

### 5.2 데이터 보호

- **전송**: HTTPS/TLS 1.2 이상
- **저장**: 민감 데이터 암호화 (AES-256)
- **SQL Injection**: Prepared Statements 사용
- **XSS**: HTML 이스케이핑, CSP 헤더

### 5.3 접근 제어

- **역할 기반**: Owner, Admin, Editor, Viewer
- **권한 검증**: 모든 API 엔드포인트에서 검증
- **감사 로깅**: 모든 주요 작업 기록
